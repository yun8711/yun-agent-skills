# 本学习项目规则（LEARNING-RULES.md）

此文件由 **Tech Mentor（`tech-mentor`）** Skill 在创建工作区时自动生成。请勿删除。

## 1. 核心使命

- 本工作区是**系统化学习 {TECH}** 的专用空间。
- 所有交互必须服务于用户明确的学习目标。
- 严格遵循 Diátaxis 框架生成内容（Tutorials / How-to Guides / Explanation / Reference）。

## 2. 行为规范（AI 必须始终遵守）

1. **前置确认**：生成新阶段内容或重大调整前，必须先确认用户当前进度和具体需求。
2. **Grounding**：所有技术解释、代码示例必须基于最新官方文档（优先使用 WebFetch / browser 工具获取最新信息）。
3. **结构化输出**：Tutorial 类内容**必须先提出详细大纲**，经用户确认后再生成完整内容。
4. **实践导向**：可运行练习与验收默认落在**仓库（或课程根）下的 `practice/`** 内。**生成或修改任何练习/示例代码前，须先读取 `resources/tech-profile.json`**（含 `practiceLayout`、`practiceMainProject`、`codeStyle`、工作区约定）。**incremental**：先在 `practice/` 内建好**完整主工程**（见 `practiceMainProject`），再在其上增量演进；各章若需隔离或并列模块，**仍在 `practice/` 下**按技术栈增子目录或其它形式，并在 `LEARNING-PLAN.md` 中可核对。**sandboxed**：各章独立子目录（可各自完整小项目）。**mixed**：计划中须写明阶段与目录边界。
5. **笔记规范**：
   - **项目内（约定）**：项目特定踩坑、代码解读、练习备忘 → 写入本项目 `notes/`；外链与资源索引 → 写入 `RESOURCES.md`，避免与 `notes/` 混用。
   - **项目外（不强制）**：个人知识库、全局笔记由用户按习惯自行处理；AI **不得**默认要求写入 `yun-notes` 或调用 `notes-capture`，除非用户明确提出。
   - 若项目根存在 `generate-index.js`，新建分类目录后运行；不存在则跳过。

## 3. 代码规范（由 tech-profile.codeStyle 决定）

以下占位符在初始化本文件时**必须**从 `resources/tech-profile.json` 的 `codeStyle`（及 `tech`、`relatedEcosystem`）填入；禁止保留未替换占位符。

- 采用 **{LANGUAGE}** + **{FRAMEWORK}**（若无框架则写「标准库 / 无」）官方文档推荐的**惯用写法**与最佳实践。
- 强制启用 **{LINTER}** + **{FORMATTER}**（若该技术栈无独立工具，写「语言内置 / 社区约定」并说明具体命令）。
- 优先采用 **{PARADIGM}**（如 Composition API / Hooks / Functional / OOP / 所有权与借用 等，与栈一致）。
- 运行与验收目标：**{RUNTIME_TARGET}**（如 `dev server`、单测通过、CLI 输出、二进制运行等）。
- 模块/函数须有清晰注释；类型或类型提示按该语言惯用方式（若适用）。
- 所有示例须在用户约定的工作区路径内可运行；`workspaceMode` 为 `in_place` 时，**仅**修改 `tech-profile` 中约定的可写目录。

## 4. 计划管理

- `LEARNING-PLAN.md` 是唯一真相来源。
- 用户修改计划后，AI 必须据此调整后续内容生成。
- 每阶段结束更新 `PROGRESS.md` 并记录自测结果。
- 持续识别学习难点（基于用户提问、代码错误模式、练习完成情况），记录到 `LEARNING-LOG.md`。
- 阶段结束或学习周期末尾，基于日志生成**总结报告 + 针对性重点强化训练**（见第 5 节分级要求）。

## 5. 学习跟踪与评价机制（完整版）

1. **记录触发条件**
   - 每次练习批改完成后，立即追加一条学习日志。
   - 每次关键提问答复完成后，立即追加一条学习日志。
   - 每章结束或里程碑达成后，更新阶段进度与阶段评价。
2. **学习日志必填字段（`LEARNING-LOG.md`）**
   - `章节/任务`
   - `重点`（已掌握项）
   - `难点`（错误模式、理解断点、实现卡点）
   - `疑问点`（未完全闭环的问题）
   - `证据`（代码路径、报错摘要、提问摘要、验证结果）
   - `建议动作`（下一步练习与复盘动作）
3. **阶段进度必填字段（`PROGRESS.md`）**
   - `章节状态`（未开始 / 进行中 / 已完成）
   - `练习完成率`
   - `测试与验收结果`
   - `阻塞项与解除状态`
4. **学习评价必填字段（`LEARNING-EVALUATION.md`）**
   - `阶段评价`：知识掌握、工程实践、问题定位、表达迁移四维结论。
   - `趋势评价`：与上阶段对比的进步点与复发点。
   - `风险结论`：当前最影响学习效率的 1～3 个风险点。
   - `强化计划`：不少于 3 条可执行任务；**每条必须包含**：
     - `难度`：`基础` | `进阶` | `挑战`
     - `预计耗时`：约 X 分钟（估计值）
     - `目标`、`动作`、`验收标准`
5. **输出要求**
   - 仅输出结论与行动项，不输出过程性讨论或推理过程。
   - 结论必须可执行、可验证，避免抽象表述。

## 6. 交互约定

- 用户说“下一阶段” → 生成下一个 Diátaxis 模块 + 练习
- 用户说“解释 XX” → 输出 Explanation 类型文档
- 用户说“更新计划” → 重新分析当前计划并提出优化建议
- 用户说“记录笔记” → 默认写入本项目 `notes/`（或用户指定的项目内路径）；若用户明确要求使用外部工具或全局库，再按其指示执行
- 用户说“批改练习” → 批改并更新 `LEARNING-LOG.md` / `PROGRESS.md`
