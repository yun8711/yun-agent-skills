# 样例摘要（电信星网类需求）

输入：分支需求 Markdown（资产详情：订阅、质量总览改名、评论）。

## 流程摘要

1. Read 需求 → 约定 mock、仅前端。
2. 对照 `assets-detail` / `technic-components/db` / `data-quality` 等落点。
3. 对话输出三块工作计划 + 12 条澄清问题。
4. 用户确认：如复用 `toApply` 且不刷新；存储单位 KB；`el-rate` 满分 5 必填；每页 10；`kd-empty`；删除二次确认等。
5. 回写同一文档：需求条文嵌入确认细节 +「工作计划清单」章节。
6. 用户明确「不要改代码」→ 止于文档。

## 文档目录

此类过程稿放项目 `req_docs/`（gitignore），避免随客户分支切换丢失或误提交。
