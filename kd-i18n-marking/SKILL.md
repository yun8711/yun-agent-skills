# KD 国际化 - 智能文本标注

本 Skill 面向**大型项目**：在控制上下文的前提下，对源码中的待译文案进行 **`t()`** 等标注；须与 **`.voerkai18nignore`**、**`voerkai18n_literal_hits.txt`**（字面量登记）、**`voerkai18n_progress.txt`**（分批队列）配合使用。

## 使用时机

- 项目文件多，需分批在源码中做国际化标注
- 全量打开源码易触达上下文上限
- 需要与 VoerkaI18n 的忽略规则一致，减少噪声文件

---

## 标注前：确认工作模式

**开始任何扫描或改源码前，须先询问用户**采用下列哪一种方式（二者互斥，按用户选择执行后续步骤）。

| 模式 | 适用场景 | 待处理文件如何确定 |
|------|----------|-------------------|
| **全量** | 项目从未做过国际化适配、未做过词条提取 | 对 **`src`** 递归扫描并经 **`.voerkai18nignore`** 过滤，得到完整待标注清单，写入 **`voerkai18n_progress.txt`**，再按批标注。 |
| **增量** | 已做过标注，但因合并其他分支或本地修改产生新的待译文案 | **仅**处理「待提交」变更中的源码：以 Git 差异为准，通常为用户指定的 **已暂存**（`git diff --cached`）与/或 **相对 HEAD 的工作区改动**（`git diff`）；只保留路径落在 **`src`** 下、且符合本节白名单与 **`.voerkai18nignore`** 的文件，据此生成或覆盖本轮 **`voerkai18n_progress.txt`**（**只含这些文件**），再按相同分批规则标注。 |

未得到用户明确选择前，不得假定全量或增量。

## 标注范围

界定**哪些路径与文件**进入待标注清单；未列入者本轮不处理。

- **目录**：仅 **`src`**（递归，不限深度）。
- **忽略**：与仓库根目录 **`.voerkai18nignore`** 完全一致——凡应被忽略的路径，**不得**写入待处理列表。
- **扩展名（建议白名单，可按项目裁剪）**：`*.vue`、`*.js`、`*.jsx`、`*.ts`、`*.tsx`。
- **路径写法**：相对仓库根目录的 POSIX 风格（如 `src/views/Foo.vue`）。

**`.voerkai18nignore`** 的创建与**默认基线内容**见 **kd-i18n-setup**「配置 .voerkai18nignore」：须在项目**接入国际化 / 发版前**完成，**不是**标注环节的产物；若仓库中缺失，应按 setup 补全后再进入标注扫描。

**小范围**：若只需处理 `src` 下个别子目录，可在扫描阶段**将根路径收窄**到该子树（仍遵守 `.voerkai18nignore`），再生成进度文件。

## 强制流程：源语言字面量匹配 → 登记 → 再标注

**不得跳过**。凡改源码做国际化包裹，**必须先**对当前文件做**字符串级**源语言检出并**落盘登记**，**再**按登记结果逐项处理；禁止仅凭通读文件直接改、仅靠回忆是否有中文。

### 匹配规则（默认）

- **对象**：当前待标注文件的全文（与 **`.voerkai18nignore`**、扩展名白名单一致范围内的文件）。
- **默认模式**：匹配 **CJK 统一汉字** Unicode 范围 **`[\u4e00-\u9fff]`**（可用 `rg`、`grep -P` 或等价方式按行/按文件扫描）。若用户声明**源语言不是中文**（或需额外匹配全角标点等），在本轮对话开头与用户对齐**等价正则/字符类**，并**全程沿用**。
- **产出**：每一条命中（每行可出现多处命中时，**按行或按连续片段**登记均可，须能定位到编辑位置）且**至少在登记中保留「路径 + 行号 + 含命中片段的原文摘要」**，便于逐项核对。

### 登记文件 `voerkai18n_literal_hits.txt`

- **位置**：仓库**根目录**，文件名 **`voerkai18n_literal_hits.txt`**。
- **版本控制**：**须加入 `.gitignore`**（与 **`voerkai18n_progress.txt`** 同策略）。
- **建议行格式**（`|` 分隔，单行一条命中；片段内换行改为空格或截断）：  
  `相对路径 | 行号 | 原文片段摘要`
- **写入节奏**（二选一，须在当轮对话内**约定并贯彻**）：
  - **按文件**：每打开一个待标文件，**先**将该文件当前所有命中**追加或合并写入**登记表，**再**开始 `t()` 标注；或
  - **按批**：对本批内每个文件在**本批内首次处理前**完成登记，再进入改源码循环。  
  **禁止**在「尚未对本文件写入任何登记行」的情况下修改该文件。

### 登记后的处理顺序（必遵）

1. **去噪判定（登记之后、改源码之前）**：对每条命中判断是否为 **「本条不标」**——**整行仅块注释/行注释**、**命中片段已落在既有 `t(...)` / `this.t(...)` 的首个字符串实参内**（含模板中 `{{ t('…') }}` 内引号间）、以及 **「明确不标」**（见下节「防遗漏」）。此类条目**不**做包裹，但**可保留在登记表中并标记 `skip`**，或从本轮待办清单中排除；**须在对话中可复核**，避免静默丢弃。
2. **逐项标注**：对其余命中，严格按 **「标注规则」** 增加 `t` / `this.t`（及非 `.vue` 的导入约定），**依序处理**直至该文件无「待标」裸露命中。
3. **关闭本文件前重匹配**：在将该文件从 **`voerkai18n_progress.txt`** 队列删除**之前**，对该文件**再执行一次**与第 1 步相同的匹配；除已允许的「明确不标」及已正确包裹外，**若仍存在源语言字面量命中 → 禁止删进度行**，须补标或对该文件进度行追加 **`| Error`**。

### 与进度文件的关系

- **`voerkai18n_literal_hits.txt`** 管 **「挖出来什么字」**；**`voerkai18n_progress.txt`** 管 **「哪个文件还没标完」**。二者**同时**使用；**不因**已有字面量登记就省略进度文件的分批与删行规则。
- 本轮结束后，用户可自行删除 **`voerkai18n_literal_hits.txt`**（不要求 Agent 代删）；若需留审计可与进度文件一并保留至人工确认后再删。

## 标注规则

`t` 函数是 voerkai18n 提供的翻译函数，并且已被全局注册，所以在组件中不需要导入即可直接使用；
在 .js等非 .vue 文件中使用时，需要使用 `import { t } from "@/languages"` 导入翻译函数再使用。

（1）插值语法，例如：

- `<h1>请输入用户名称</h1>` 需要替换为 `<h1>{{ t("请输入用户名称") }}</h1>`
- `<input type="text" placeholder="请输入手机号"/>` 应替换为 `<input type="text" :placeholder="t('请输入手机号')"/>`

（2）`<script>` 的 **Options API** 中，在 `data`、`computed`、`methods`、生命周期钩子等选项里使用 **`this.t()`** 包裹待译文案，语法如下：

- 简单用法：`const a = this.t('全部')`（须写在 `methods` 或钩子的函数体内，**不可**放在 `export default` 顶层直接使用 `this`）
- 命名插值：在 `t` 的第一个参数中用 `{变量名}` 占位，第二个参数传对象，如：`this.t('我姓名叫{name},我今年{age}岁', { name: 'tom', age: 12 })`
- 位置插值：用 `{}` 占位，第二个参数传数组，如：`this.t('我姓名叫{},我今年{}岁', ['tom', 12])`

（3）**`props` 默认值**：**禁止**在 `props` 的 `default`（含 `default: () => ...`）里使用 **`this.t(...)`** 作为可译默认文案。原因：`default` 初始化阶段 **`this` 不可用或与运行时实例不一致**，且不利于切换语言后依赖该默认值的展示更新。若默认展示内容需要翻译，**须改为 `computed`**（或 `computed` + 现有 prop 推导），在计算属性内写 **`this.t(...)`**，模板中绑定该计算属性。

```javascript
// 错误：禁止在 props.default 中使用 this.t
// props: { label: { default() { return this.t('操作') } } }

// 正例：可译默认文案放到 computed，模板里用 labelText
export default {
  props: {
    labelKey: { type: String, default: '' },
  },
  computed: {
    labelText() {
      return this.labelKey ? this.t(this.labelKey) : this.t('操作')
    },
  },
}
```

```vue
<template>
  <div>
    <h1>{{ t("请输入用户名称") }}</h1>
    <div>
      <span>{{ t("用户名:") }}</span><input type="text" :placeholder="t('邮件/手机号码/帐号')" />
      <span>{{ t("密码:") }}</span><input type="password" :placeholder="t('至少6位的密码')" />
    </div>
  </div>
</template>
<script>
export default {
  data() {
    return { maxUploadMb: 10 }
  },
  methods: {
    demo() {
      const a = this.t('全部')
      this.t('超过最大上传限制{}M，请重新选择上传', [this.maxUploadMb])
    },
  },
}
</script>
```

（4）**类似`kd-column-text` 组件的 `p-l`**：`p-l="prop值,列标签文案"` 表示 **`prop` + `label`** 的合并写法（与 **`el-table-column`** 的语义一致）。标注时须**拆成两个属性**：**`prop`** 仍为字段键；**`label`** 写 **`:label="t('列标签文案')"`**，其中 **`t()` 的参数必须是加引号的字符串**（待提取词条）。

- 标注前：`<kd-column-text p-l="initiator,申请人"></kd-column-text>`
- 标注后：`<kd-column-text prop="initiator" :label="t('申请人')"></kd-column-text>`

## 防遗漏（必遵）

遗漏多来自**只处理模板正文、不扫脚本与属性**。本 Skill 要求：**同一文件内凡属「用户可见文案」的裸露字面量，须在一次处理中收齐**，不得依赖「看起来改完了」。

### 单文件须同时覆盖的区域

- **`<template>`**：文本节点 + 所有**可能展示给用户**的属性（静态与动态均需核对），包括但不限于：`label` / `:label`、`title` / `:title`、`placeholder` / `:placeholder`、`alt`、`aria-*` 中含语义的、`empty-text`、`no-data-text`、对话框/抽屉的 `title`、按钮与表单项的展示类 prop、表格列的 `label`（含 **`el-table-column` / 封装列组件**）、`formatter` 等回调**返回给界面**的硬编码字符串、Tooltip/ Popover 的 `content` / `title` 等。
- **`<script>`（含 `export default` 与各选项）**：`data` / `computed` / `watch` / `methods` / 生命周期中**面向 UI** 的字符串；**`this.$message` / `Message` / `MessageBox` / `Notification`** 等弹层的第一参数或 `message`、`title` 等字段；**路由** `meta.title`、面包屑等配置中的展示文案；**校验规则**中的 `message`；**列配置、菜单项、选项列表**等数组/对象里的 `label`、`name`、`text` 等展示字段；**合并写法**（如 **`p-l`**）须按上文拆解后分别标注，**不可只改一半**。
- **Vue 3 / `<script setup>`**：与项目实际一致——若模板仍用全局 `t`，则与 Options API 模板规则相同；脚本内若需 `t`，按 **kd-i18n-setup** 与 VoerkaI18n 在工程里的用法（如组合式 API 中的 `t`）处理，**同样须扫全段脚本**。

### 明确不标（避免为「补全」误伤）

- 接口字段名、纯技术 key、路由 **path**、不需翻译的日志/`console`、已是 **`t(...)` / 词条 key 变量`** 的调用链（勿重复包裹）、纯数字/纯符号。

### 每文件收尾自检（本批内必做）

与 **「强制流程：源语言字面量匹配 → 登记 → 再标注」** 中 **「关闭本文件前重匹配」** 一致：删 **`voerkai18n_progress.txt`** 中该行**之前**，须确认重匹配后无待译裸露源语言字面量（或已 **`| Error`**）。

## 标注策略

在**已确定的标注范围**与**已对齐的标注规则**之下，进行**分批、记账、收尾**，避免单次对话过载。

### 进度文件 `voerkai18n_progress.txt`

- **位置**：仓库**根目录**，文件名 **`voerkai18n_progress.txt`**。
- **内容**：**待自动标注队列** + 可选的**容错留痕行**（见下「容错标识」）；每行至少含文件路径与 **字节大小**（扫描时的 `size`，供组批估算）。
- **行格式**（`|` 分隔；容错标识写在**该行末尾**）：

```text
src/views/Foo.vue | 12345
src/components/Bar.js | 8901
src/components/NeedReview.vue | 5600 | Error
src/utils/LogicTouched.js | 3200 | Modify
```

- **首次写入（本对话轮）**：**全量模式**下，完成 **`src` 扫描 + `.voerkai18nignore` 过滤** 后写入完整待处理列表；**增量模式**下，仅将 Git 差异中符合条件的 `src` 文件写入列表（无差异文件则不需虚构条目）。新写入行**只有**「路径 `|` size」两段，**不带**容错后缀。
- **每批之后（必做）**：对本批内**已正常按规则完成标注**且无下述容错情形的行，从该文件中**删除对应行**（只删清单记录，**禁止**删源码文件）。遇容错情形时**不得删除该行**，应**在原行末尾追加**标识并重写文件（路径与 size 段保持不变）。**立即保存**后再组下一批。
- **版本控制**：将 **`voerkai18n_progress.txt` 加入 `.gitignore`**。

#### 容错标识（`Error` / `Modify`）

用于标注过程异常或改动业务逻辑时的**留痕**，供用户最后对照进度文件**人工审核**；**勿**在收尾时删掉这些行。

- **` | Error`**（前段仍为「路径 `|` size」）：对该文件的标注**出现问题**（无法稳妥完成、`t()` 边界不清、冲突过大致使放弃本批修改等），在该行**最末尾**追加 **` | Error`**。
- **` | Modify`**：标注过程中**顺带调整了该文件内的逻辑**（除纯文案包 `t()` 之外的**行为 / 条件 / 数据结构**等），在该行**最末尾**追加 **` | Modify`**。

- **写法**：在整行**最末尾**追加 **` | Error`** 或 **` | Modify`**（注意 `|` 前有空格，与现有列风格一致）。**若同一文件同时适用**（例如先改逻辑再仍存疑），可写 **` | Error | Modify`**（先 `Error` 后 `Modify`），或**只保留 `| Error`** 以突出需优先排查——须在当轮对话中简短说明取舍。
- **组批**：读取进度文件时，**仅将「行末不含 `| Error` 与 `| Modify`」的行**计入待标注队列并参与条数/体积上限；已带容错后缀的行**不再自动纳入后续批次**，避免重复机处理；用户审阅、修正源码后，可**手动删除该行**或**去掉后缀**再按需重新写入队列。
- **与「删行」规则的关系**：无后缀且本批已标完的 → **删行**；有后缀的 → **保留行**（仅更新为带后缀形式）。

### 批量大小（固定上限）

自进度文件**自上而下**组批（**仅**包含**行末无** `| Error` / `| Modify` 的队列行，已留痕行不参与本统计），每一批**同时满足**：

1. **文件个数**：至多 **10 个**；
2. **体积**：本批各行「字节数」**合计**不超过 **50KB**（即 50×1024 字节，与进度文件 `size` 列同单位）。

**单文件超过 50KB**：该文件**单独成一批**（本批仅此 1 个文件，不受 50KB 合计限制），避免永久卡死。

组批时优先凑满「条数或体积」中**先触顶**的那条约束：即从队首依次纳入文件，一旦再加一个会违反上述任一上限，则本批结束。

### 单批与批次衔接

- **本批内**：仅做源码标注；**不做** `build`、**不做**额外总结。**每个文件**均须先完成 **「强制流程」** 中的匹配与登记，再改源码。
- **本批结束**：更新 **`voerkai18n_progress.txt`**（删掉本批中**已正常完成**的对应行；对 **`| Error` / `| Modify`** 行则**改写为带后缀并保留**）→ **立刻**按上节组下一批，直到**队列中**（行末无容错后缀的行）无剩余。

### 全部完成

- 进度文件中**已无「行末不带 `| Error` / `| Modify`」的队列行**时，本轮自动标注告一段落：**告知用户**；并请用户**对照文件中仍保留的 `| Error` / `| Modify` 行**逐项复核对应源码。用户确认无误后，**自行删除**根目录 **`voerkai18n_progress.txt`**（本 Skill 不要求 Agent 代删）。若进度文件**已无任何行**，可直接提示删除该文件或进入下一环节。

### 执行顺序摘要

1. **向用户确认**采用 **全量** 或 **增量**（见「标注前：确认工作模式」）；未确认不开工；若源语言**不是**默认中文汉字集，一并确认匹配用字符类/正则。
2. 确认 **kd-i18n-setup** 与 **`.voerkai18nignore`** 就绪；**将 `voerkai18n_literal_hits.txt` 与 `voerkai18n_progress.txt` 一并列入 `.gitignore`**（若尚未）。
3. **全量**：扫描 **`src`** 并过滤 → 生成 **`voerkai18n_progress.txt`**。**增量**：按用户约定的 Git 范围取变更文件路径 → 筛到 **`src`** + 白名单 + ignore → 写入 **`voerkai18n_progress.txt`**。
4. 循环：按「≤10 文件且合计 ≤50KB」仅对**无容错后缀**的行组批 → **对批内每个文件强制执行**「**匹配 → 写入 `voerkai18n_literal_hits.txt` → 去噪 → 逐项标注 → 关文件前重匹配**」→ 更新 **`voerkai18n_progress.txt`**（**正常完成的删行**；**异常或改逻辑的**在行末追加 **`| Error`** / **`| Modify`** 并**保留行**）→ 下批，直至队列清空。
5. 提示用户**审核**进度文件中 **`| Error` / `| Modify`** 留痕行及（如需）**`voerkai18n_literal_hits.txt`** 中带 **`skip`** 或存疑条目后，再删除 **`voerkai18n_progress.txt`** / **`voerkai18n_literal_hits.txt`**（若本轮曾创建/使用）。

---

**完成标注**（含对 **`| Error` / `| Modify`** 行的**人工审核**）**并删除进度文件后**，可进入 **kd-i18n-translation**（翻译管理）环节。
